# Architecture

Cross-Tab-Sync keeps one shared set of open tabs between Safari on macOS and Brave on Windows through a small self-hosted service. This document is the current system design; [PROTOCOL.md](PROTOCOL.md) is the wire contract and [ROADMAP.md](../ROADMAP.md) the delivery plan.

## System overview

```
Safari (macOS)                       Brave (Windows)
┌──────────────────────┐             ┌──────────────────────┐
│ Swift app wrapper    │             │                      │
│ ┌──────────────────┐ │   HTTPS     │ ┌──────────────────┐ │
│ │ WebExtension     │◄├─────┐ ┌────┤►│ WebExtension     │ │
│ │ (shared TS core) │ │     │ │    │ │ (shared TS core) │ │
│ └──────────────────┘ │     │ │    │ └──────────────────┘ │
└──────────────────────┘     ▼ ▼    └──────────────────────┘
                     ┌─────────────────┐
                     │ Go service      │  single user, single session
                     │ SQLite (WAL)    │  devices · ownership · ops log · snapshots
                     │ behind Caddy    │
                     └─────────────────┘
```

Exactly one device is the **owner** (publisher) at a time. The owner pushes operations; followers pull and apply them in the background. The server is the arbiter of ownership and revision order, never a tab-level merger of browser UI state.

## Major components

### Go service (`server/`)

- **HTTP API** on the standard library `net/http` mux (Go 1.22+ method routing). JSON bodies, bearer-token auth, structured errors, payload limits. No framework.
- **Store** on SQLite via `modernc.org/sqlite` (pure Go, no CGO, trivial cross-compile for the VPS). WAL mode, single writer, `database/sql`. Migrations are embedded `.sql` files applied in order at startup.
- **Session engine**: applies operation batches inside one transaction. Enforces owner generation, assigns revisions, coalesces duplicate URLs, keeps closure tombstones, records per-operation results for idempotent retries.
- **Recovery snapshots**: before any batch that closes or navigates entries, the open-entry set is saved; a bounded number is retained.
- **CLI**: `serve` and `pair-code` subcommands. Configuration from environment variables.

### Extension (`extension/`)

- **`src/core/`**: browser-agnostic sync logic. Pure functions and small state machines: eligibility filtering, local mapping (`tabId ↔ entryId`), duplicate counting, planning what to open/close/navigate locally, pending-operation journal, ownership state. This is where almost all unit tests live.
- **`src/adapter/`**: a `BrowserAdapter` interface (tabs, windows, storage, alarms, events) and one implementation over the `chrome.*` promise API. Safari and Brave both expose this API; the adapter isolates the few differences found during capability validation.
- **`src/background/`**: MV3 service worker entry. Wires events to the core, runs alarms, talks to the backend over `fetch`. Holds no in-memory state that is not also in `storage.local`.
- **`src/popup/`**: plain HTML/CSS/TS status page with **Hand over** and **Continue here**, pairing form, and status (owner, last sync, pending, errors).
- **`manifests/`**: one manifest per browser; shared fields are generated from a base at build time.

### Safari wrapper (`safari/`)

A minimal Swift macOS app whose only job is to host the extension. Produced from `extension/dist/safari` by Apple's converter; no native messaging and no native logic. Local testing uses Safari's *Allow unsigned extensions*; distribution is Developer ID + notarization (documented in the release epic).

## Key decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Single session, single user | One shared session per server instance | Matches the product; avoids multi-tenant complexity. Devices pair into the one session. |
| Ownership | Server-held owner + monotonically increasing **generation** | Stale owners are rejected by generation mismatch, not by timing. Takeover increments the generation atomically. |
| Change model | Append-only **operation log**; `revision` = sequence number of the last applied op | Followers catch up with `changes?since=`. Deterministic replay. Retry safety via client-generated `opId`. |
| Deletion | Explicit `close` ops only; closed entries stay as tombstones | Snapshot absence never deletes. Tombstones stop stale devices from resurrecting closed tabs. |
| URL identity | Exact browser-reported URL string, http/https only | Preserves query and fragment as specified. Coalescing happens on the server so both devices converge. |
| Entry identity | Client-generated UUID at open time | Lets devices map local tabs to shared entries before the server has acknowledged. |
| Transport | JSON over HTTPS, bearer token per device, SHA-256 hashed at rest | Simple, debuggable, works from service workers. HTTPS enforced outside local development. |
| Encryption | TLS in transit; plaintext URLs at rest on the user's own VPS | The server must read URLs to coalesce duplicates. End-to-end encryption is deferred; it would need client-side dedup via an HMAC of the URL. Logs never contain URLs or tokens. |
| Extension build | esbuild + TypeScript, no framework | Two small bundles (worker, popup). No React/Vue; the popup is a status page. |
| Browser API | `chrome.*` promise API directly, no polyfill | Both Safari and Brave support it under MV3. A thin adapter interface keeps the core testable. |
| Sync cadence | `alarms` every 5 minutes, immediate on takeover and manual actions | Service workers are suspended; alarms are the only reliable scheduler. |
